# 手控制器串口上位机

## 摄像头参数上传（2026-10-03）

手控制器通过内置 Wi-Fi 连接 `Camera-D6A4`，向 `ws://192.168.4.1/ws/upload` 每 300 ms 上传一份最新状态。SPI NRF24 的控制与飞机回传仍由原任务处理。上传任务优先级 2，低于原控制任务；一个数据包收到确认后才发送下一份，发送或确认超时会关闭连接并重连，不保存离线队列或补发积压数据。

上传内容为血氧、**手控输入电压（V，无电量百分比）**、飞机 Pitch/Roll、飞机测距。`main/telemetry.c` 从内存状态复制快照，不解析 USB 日志，也不使用手控自身姿态代替飞机姿态。飞机数据使用 `air_pitch_cdeg`、`air_roll_cdeg`、`air_distance_cm` 和对应有效位；当前飞机距离字段仍为预留无效值，因此页面显示 `--`。无线模块异常或没有飞机回传时，飞机参数同样显示 `--`。

`main/input_voltage.c` 使用 GPIO15 / ADC2_CH4 单次校准采样。原理图 R7=10kΩ、R10=10kΩ，ADC 前串联 R9=499Ω，因此 ADC 引脚电压乘以 2 还原 VCC_IN。每约 1 秒短时间采样取均值，不进行电量估算；切到 USB 供电时显示实际输入电压。ADC2 被 Wi-Fi 占用时丢弃超时结果，采样失败显示无效，不能把错误码或饱和值当电压。

采样点限制：`XFJ (2).pdf` 第 1 页中 R7 上端为 VCC_IN，电池接口 H1 正极为 VBAT_IN，二者不是同名网络。2026-10-03 用户确认电池端实测 4.14 V；拔掉手控 USB 后，相机仍收到 5129～5132 mV 的新读数，序号从 342 增至 378（`build/voltage-diagnosis.log`），已排除页面残留旧值。前端仅除以 1000 显示。图纸引脚/分压与代码一致，实板 VCC_IN 及 R7/R10 中点电压未测；目前不能判定是供电路径、实装分压还是 ADC 偏差，也不能断言 5.13 V 来自 USB。

用户随后明确要求按当前“5.13 V 对应电池 4.14 V”类推，因此新增单点比例校准：`显示毫伏 = round(分压还原毫伏 × 4140 / 5130)`，系数约 0.80701754。每次新采样都应用该系数；无效采样仍无效，不固定显示 4.14 V，也不换算电量百分比。`Camera telemetry uplink` 菜单的 `HAND_VOLTAGE_REFERENCE_MV` / `HAND_VOLTAGE_READING_MV` 保存参考值和校准前读数（单位 mV），二者相同可恢复单位增益；板级默认值已保存于 `sdkconfig.defaults`。每 5 秒诊断日志保留 ADC 原始均值、引脚毫伏、分压还原值和校准值，便于以后对照。该系数是用户指定条件下的一点对齐，不等于已证明采样的是电池端或已验证整个放电区间、USB 供电切换后的精度。

电压校准已随“控制器”任务的血氧更新统一烧录，写入哈希验证通过（`build/spo2_flash.log`）。手控实机日志为 ADC 原始均值 2994、引脚 2569 mV、分压还原 5138 mV、校准后 4146 mV、16/16 有效采样；相机连续收到序号 73、91、109、127，对应 4149、4146、4145、4145 mV，确认校准结果实际进入上传链路。详情见 `build/voltage-verification.json`、`build/voltage-runtime.log`。烧录后的采样是在手控 USB 接着时取得，尚无用户对拔线后的校准显示复测结论。

协议定义及校验共用 `../shared/hud_protocol.h`、`../shared/hud_protocol.c`。协议 v1 使用整数单位：`spo2_x10` 为 0.1%，`voltage_mv` 为 mV，`pitch_cdeg` / `roll_cdeg` 为 0.01°，`distance_cm` 为 cm；无效值用 JSON `null`。分别携带 `spo2_age_ms`、`voltage_age_ms`、`air_age_ms`，重复上传不会刷新源数据的测量时间。`session` 区分启动，`seq` 检查重复及倒序。血氧改为随新 PPG 数据滚动计算，有有效结果立即更新源时间；上传任务每 300 ms 转发最新结果，不再每次等满 5 秒。

在 `idf.py menuconfig` 的 `Camera telemetry uplink` 中可更改热点名称、密码和相机地址。默认名称对应当前相机 MAC 尾号 D6A4，密码为空。Wi-Fi 使用 RAM 配置，不擦除 NVS。网页链路只负责显示。上位机启动的会话使用 USB 心跳；LED1 实体按钮启动的会话由手控独立控制任务维持心跳。

离线检查：`tests/test_hud_protocol.c` 覆盖空值/零值、单位、源数据年龄、畸形消息和序号回绕；相机目录 `tests/hud_browser.cjs` 覆盖电压、数据超时、连接恢复和页面显示。

飞控现以 `../官方小飞机的程序/主控程序(keil MDK打开)+外扩激光+光流20261001/` 为基础，停止部署 `recovered_c`。官方 `HAL/control.c`、`USER/INIT.c`、`MATH/pid.c`、`MATH/imu.c`、`CONFIG/TIM.c` 保持原文件；新增 `HAL/hand_link.c` 负责 HC3、遥控通道转换和操作阶段。手控制器只发送 HC3；原遥控器接收页仍用于诊断。

1. 手控上电后先平放静止约 3～4 秒，自动校准陀螺仪零偏及平放零点；检测到晃动会重新采样。校准完成且无线模块就绪即自动连接飞机，只发送低油门锁定包，保持锁定、不转电机。飞机后开机也会接入。平放手控、按下并松开 LED1（GPIO10）才执行解锁确认 → 缓升起飞；LED2（GPIO11）按下急停。上位机的平放校准、显式解锁/起飞按钮仍可使用。
2. 无地面稳定等待。地面读数 0、测距暂不可用不阻止显式起飞。起飞从官方启转门槛 RC=1101 开始，按原公式 `200 + 0.45 × (RC−1000)` 得到约 245，公共推力在 2 秒内从 245.5 增加至 500（RC≈1667），对应 127.25 单位/秒。此速度仅用于“缓升起飞”，由飞控执行。相对起飞参考升高至少 200 mm（恢复原先的 20 厘米）、持续 100 ms 后接入官方定高 PID，保持接入时的实测高度。通道 1500 表示保持高度，不是 1500 mm 的目标高度。15 秒未确认离地会告警并转自稳手动，保持切换前推力，需平放后接管；不会因测距缺失直接断油门。
3. 官方定高基准 500，公共推力范围 0～800；保留官方高度、速度和姿态运算。没有搬入回读版的地面等待、冻结高度 PID、200 ms 推力过渡等附加逻辑。
4. 掌心按住优先：Roll/Pitch/升降/Yaw 均为 1500，在定高模式下停止方向与升降指令。松开掌心并平放满 1 秒后 Pitch=1700 前进；确认期间和过渡姿态保持四轴 1500。左右倾斜默认 Yaw=1300/1700，仍可在上位机停止发送后改选 Roll；每次上电默认 Yaw。抬手 1800 上升、下垂 1100 下降；官方垂直目标速度 +250/−350 mm/s。飞控开启光流时转换为 1200/1800，偏航转换为 1100/1900，以跨过官方方向阈值；姿态模式保留 ±8°目标。每次只有一个手势。
5. 点击降落使用官方下降逻辑。缓升阶段点击降落，或降落中失去定高，会逐步减小手动推力至停止。急停按钮或 Esc 发送 DISARM；只有收到新鲜锁定回包才显示确认。

### 使用原配小遥控器

原配遥控器仍使用自己的 AA 协议和“油门最低 → 最高 → 最低”解锁方式。使用前在串口上位机点击“锁定并停止”（或关闭手控制器），等待约 0.6 秒释放手控占用，再用原遥控器重新解锁；无需重启飞机。不要同时让两台遥控器发送，它们使用相同的频道和地址。

本次兼容修正：HC3 停止/超时后释放占用并清除原遥控器旧解锁步骤；有源控制正在解锁飞行时，不允许另一种协议接管。原遥控器的失联检查使用真实 600 ms 计时，只有有效 AA 帧刷新，不再用主循环空转次数重置无线模块。原配遥控器的八通道、AUX1 切换、摇杆解锁保留。离线新增 13 项原遥控器及切换测试，共 160 项通过；实机 100 次锁定采样，原遥控器有效包增加 2783 帧，四路 PWM 全为 0。

### 异常处理与当前限制

| 条件 | 处理 |
| --- | --- |
| 回传延迟 300 ms / 中断 600 ms | 上位机告警，继续上行；限制新的解锁、起飞、恢复定高 |
| 飞控超过 600 ms 未收到有效控制 | 锁定，立即清零四路 PWM；计时来自独立 1 ms 时基 |
| 官方算法退出定高 | 保留姿态控制，按刚才公共推力反算手动油门；限于官方手动范围约 205～650。先平放再上下调节，25 推力单位/秒；不保证悬停 |
| 高度恢复 | 原始高度 50～3499 mm 持续有效 500 ms 后，可平放点击恢复定高；按官方基准 500 接入 |
| 上位机会话的 USB 心跳超过 750 ms / 手控姿态失效 | 手控停止并发送锁定 |
| 实体按键会话的独立控制任务停止刷新超过 750 ms / 手控姿态失效 | 手控停止并发送锁定；此模式不依赖 USB 上位机心跳 |
| 飞控 IMU 超过 100 ms 无新样本 / 原倾角保护 / 无线寄存器异常 | 锁定；原因保留到新会话 |

官方测距处理保留：收到 0 时原飞控高度缓存保留上次非零值；高度异常连续约 300 ms 或连续 I²C 失败约 66 ms 会退出定高。上位机另报原始读数，地面 0 是有效诊断值。接入、恢复定高时使用官方 500 基准，未验证实飞切换是否平顺。

飞机四路指示灯同步显示连接和解锁状态，手控制器、原配遥控器一致：

| 飞机状态 | 四路指示灯 |
| --- | --- |
| 未连接或控制数据超过 600 ms 未更新，已锁定 | 慢闪：亮 300 ms、灭 300 ms |
| 已收到当前遥控器有效数据，尚未解锁 | 快闪：亮 100 ms、灭 100 ms |
| 解锁成功、准备起飞及飞行中 | 四灯常亮，定高和光流模式也常亮 |
| 人工锁定，遥控连接仍在 | 回到快闪 |

灯光按飞控实际接收和解锁状态切换；解锁后立即常亮。指示灯状态不能替代串口上的解锁确认。

## 飞机遥测（Pitch / Roll / 距离预留）

串口上位机第四页“飞机遥测”，数据来自飞机自身 IMU。“手势 → 遥控输出”点击“连接飞机”后才开始，无需解锁。飞机在有效 HC3 会话下每 300 ms 选取一个已有回复时隙发送遥测，按固定时钟推进，避免时隙延迟累计；实际到达时间含无线时隙与丢包抖动；不额外增加无线发射次数。控制和基础状态仍约 50 ms 更新。点击“锁定并停止”、会话超时或 USB 断开后，页面清空；连接正常但遥测超过 1000 ms 也清空，避免旧读数冒充实时值。

距离是后续独立测距模块的预留字段，单位 **cm**，有效范围 **20～720（含边界）**。目前固定发送无效标记 `0xFFFF`，上位机显示“-- cm / 测距模块未接入”。现有定高高度仍按原来的 mm 字段传输，不能代替该距离。

### HC3 遥测扩展帧（32 字节，命令 0x83）

多字节数值使用大端；有符号角度使用二进制补码。复用现有频道、地址、会话和 CRC，无需另配通信协议。

| 字节偏移 | 长度 | 内容 | 编码 |
| --- | --- | --- | --- |
| 0–1 | 2 | 帧头 | `48 43`（HC） |
| 2 | 1 | 版本 | `03` |
| 3 | 1 | 命令 | `83`（TELEMETRY） |
| 4–7 | 4 | 会话 ID | uint32，匹配当前连接 |
| 8–9 | 2 | 回复序号 | uint16，回显所接收的控制序号 |
| 10–11 | 2 | 飞机状态 | bit0 解锁，bit1 定高，bit4 光流 |
| 12–13 | 2 | 状态原因 | 沿用 HC3 原因码 |
| 14–15 | 2 | 实际油门通道 | uint16 |
| 16–17 | 2 | 已接受的控制命令 | uint16 |
| 18–19 | 2 | 累计有效上行包 | uint16，低 16 位 |
| 20–21 | 2 | 飞机 Pitch | int16，角度×100；无效 `0x8000` |

两路震动电机在原理图中分别接 H3（MOT0→GPIO18）和 H4（MOT1→GPIO17）。GPIO 输出高电平经 Q3/Q4 拉低 AO3401A 栅极，使对应电机通电。图中 R11、R13 为 0 Ω，R12、R14 为 NC，因此电机供电选的是 **1.8 V**；实际震感取决于所装电机能否在该电压下启动。

## MAX30102 实时读取与血氧更新

2026-10-03：按用户要求撤销资料包中的 Maxim 算法试用，恢复至试用前的 `esp_health` 版本、ADC/LED/FIFO 配置及结果保留逻辑。用户原始资料包保留，项目内已移除试用算法文件。 恢复版本已通过编译、烧录哈希校验及 8 秒串口验证（80 帧，JSON 错误 0，采样正常），上位机已重新打开。

原实现先等待 32 点读取批次，再凑满 500 点（约 5 秒）计算，计算后清空。现在每次只读取 FIFO 已有的样本，不等待批次填满；最新 RED/IR 立即写入状态，串口 `@HC:` 目标周期 100 ms 上报。原始值不再按 32 点做软件平均，传感器原有 4 倍硬件平均仍保留，实际输出约 100 Hz。

血氧复用 `espressif/esp_health`：有新数据就调用计算，最少两点是其 API 条件；最多保存最近 500 点连续历史，满后滚动移除最旧数据，不清空重攒。没有新增“等 5 秒”或等待多次有效结果的门槛。恢复库默认相关性 0.8、周期质量 0.5 门限（旧值 0.55 / 0.30 过于宽松），仍检查有限数值及 70～100% 算法范围；这不代表临床准确性。首次有效百分比依赖脉搏质量，不能保证接触瞬间给出。手指离开、I²C 错误、FIFO 溢出或超过 250 ms 没有新样本会清空有效性和计算历史，不混用断续样本。

佩戴检测仍以 32 个实际样本为一组处理，不因小批次读取而缩短其判断时长；未检测到手指时也实时上报 RED/IR。波形变平不再等同于手指移开：IR 连续 3 组低于 5000 才判离开，约 1 秒消抖。计算窗口另加接触突变剔除：10 点以内红光或红外变化大于 3%（最小 300 ADC 计数）时清空历史、跳过突变点。这是根据实测接触跳变设置的经验规则，不延迟原始数据，也不对百分比强制平滑。

显示按一次接触会话保留：首次尚无有效值显示 `-- / 测量中`；首次有效值到来立即显示；后续算法无效时保留本次接触的上次有效值并标注“保持上次有效值 / 等待更新 / 距今秒数”；新的有效结果直接替换。移开后清空，再次按下不沿用上次接触的数值。USB 断开或传感器读取故障也清空，不能继续确认接触时不冒充实时测量。

GPIO15 已接电压采样，不能代替 GPIO16。NRF24L01 模块供电接 3.3 V，模块附近建议增加 100 nF 和 10 µF 去耦电容。`idf.py menuconfig` 中的 `nRF24L01 Configuration` 可调整 SPI 引脚、时钟频率和频道；本工程默认值同时保存在 `sdkconfig.defaults`。

“连接飞机”按钮要求手控本地 `rc_ready=1`。若显示“手控 NRF24 未就绪”，说明模块读写自检未通过，尚未开始发包；应先检查模块供电和 SPI 接线。模块恢复识别后按钮自动恢复可用，仍由用户点击连接。

`main/nrf24_demo.c` 在独立任务中调用现有 MiRF 驱动。由于 NRF24L01 没有芯片 ID 寄存器，上电先在 CE 为低时执行两个频道值和两组五字节地址的写入回读，再校验配置、地址、FIFO，成功后进入接收模式。未接模块、读写不匹配时每 5 秒重试，运行期间掉线或复位也会重新检测。

当前接收原 STM32 遥控器：频道 **1（2401 MHz）**、**1 Mbps**、**CRC16**、固定 **32 字节**，地址按 SPI 写入顺序为 `E1 E2 E3 E4 E5`。手控制器启用接收管道 1；管道编号是接收端本地设置，可接收对方 TX 地址匹配的数据。自动应答关闭；上电默认只接收，点击上位机“连接飞机”后可发送控制帧。IRQ 供日志观察，收包轮询 FIFO，不要求连接 IRQ。

`main/remote_protocol.c` 校验固定长度、帧头 `AA AF 03 1B` 和第 31 字节累加和（前 31 字节和的低 8 位）。第 4～19 字节解出八个大端 uint16：Roll、Pitch、Throttle、Yaw、AUX1～AUX4。第 20～30 字节只参与校验，不解析为通道。原遥控程序会向第 20～25 字节复制结构体外的数据，因此不能假定该区域全为零；本接收端兼容此行为。通道按原始值显示，不伪造或钳位收到的数据。

上位机的“原遥控器 · 无线接收”页，显示八通道、有效包数、格式/校验错误包数、最近约 1 秒有效收包速率，以及距最后有效包的时间。条形图显示 1000～2000 区间，数值标签保留完整原值。超过 500 ms 无有效包或模块掉线，八通道显示 `--`；USB 状态帧超时同样清空。传感器、手势、灯和电机仍在另一个页签。接收包数不等于发送包数，协议没有序号，不能据此精确计算丢包率。

收包循环最多每轮读取 3 包，再让出至少一个 RTOS tick；普通日志每 5 秒汇总，避免逐包打印影响接收。有效数据经 USB 的 `@HC:` 状态帧每 100 ms 上报。无线收到的通道只用于显示，不改变本机手势、灯光或电机输出。

状态每 5 秒打印一次；没有匹配参数的发送端时 `RX=0` 正常。`SPI self-test PASS` 只证明 SPI 寄存器访问和配置回读成功，CE/IRQ 的实际连线及无线链路仍需两端收发验证。遇到 `probe failed`，按日志中的期望值/读回值检查电源、共地和 SPI 接线；全 `0xFF` 或全 `0x00` 都不能当作检测成功。检测失败时额外输出 CONFIG/AW/RF_CH/STATUS，并临时切换 MISO 输入的弱下拉/弱上拉读取 STATUS，随后恢复无上下拉。如果分别为 `0x00` / `0xFF`，提示返回线可能没有被模块驱动，仍需检查模块端电源、CSN 和 MISO，不能仅凭软件认定模块损坏。SPI 已由最初的 4 MHz 降为 500 kHz 以便排查飞线通信。

### 上电陀螺仪零偏校准（2026-10-04）

继续使用现有 `waveshare/qmi8658 2.0.1` 驱动读取 QMI8658A，单位显式设为 mg / deg/s。传感器启动稳定 250 ms 后，`main/gyro_calibration.c` 收集至少 200 个新样本，且连续静止时间不少于 2000 ms；计算 XYZ 角速度均值，之后每个陀螺仪样本先扣除对应零偏，再进入原互补滤波。相同采样窗口的加速度均值设置初始姿态，并自动记录手势平放零点；手动平放校准仍只改变手势参考，不重做陀螺仪零偏。

静止判据为加速度模长 900～1100 mg、每轴角速度绝对值不超过 5 deg/s、窗口内各轴角速度极差不超过 1 deg/s、加速度极差不超过 30 mg。任一判据失败、样本间隔超过 250 ms 或读取错误都会清空尚未完成的窗口；恢复静止后重新采样。正常任务调度造成的短暂读取延迟不直接判为运动，但仍需收齐 200 个样本，因此实际完成时间可能稍长于 2 秒。这些是本项目的经验阈值，不能识别所有缓慢匀速转动，因此校准时应放在静止桌面。未完成前不发布有效姿态，不允许解锁/起飞，也不会在校准结束后补执行此前被拒绝的按键。上位机显示进度、晃动重试或读取异常。

零偏仅保存在本次启动的内存中；完成后不再自动重新学习，即使运行中出现晃动或 I²C 故障。重启重新校准，不写入 NVS。该功能不进行加速度计比例系数或陀螺仪灵敏度标定；QMI8658A 数据手册中的内置 COD 主要用于 X/Y 灵敏度校准，不替代这里的静止零偏估计。参考：[QST QMI8658A 数据手册](https://www.qstcorp.com/upload/pdf/202301/13-52-25%20QMI8658A%20Datasheet%20Rev%20A.pdf)、[Rapid Gyroscope Calibration（静止均值估计零偏的说明）](https://arxiv.org/abs/2409.00488)。

离线验证：`tests/test_gyro_calibration.c` 覆盖已知三轴零偏、带噪声样本、静置倾斜安装、时间及样本数双门槛、重复/中断采样、三轴运动与异常值、计时回绕和完成后冻结零偏。实体按键及 HC3 状态机测试覆盖姿态无效时拒绝起飞；上位机测试覆盖校准进度、运动/故障提示、完成显示及操作限制。

实机验证：ESP-IDF 6.0.3 编译、烧录哈希校验及 35 项上位机检查通过。首轮发现 50 ms 的采样间隔限制会因实际出现的 53 ms 读取间隔反复重置窗口，已改为 250 ms，保留全部静止判据和 200 点门槛。最终静置启动约 3.6 秒后完成，采样窗口 3237 ms / 200 点，三轴零偏约 −2.1495 / +0.1411 / −0.3827 deg/s。随后相对 Pitch/Roll 均约 0°，自动连接飞机；15 秒只读验证 151 帧、JSON 错误 0，发送阶段仅 0/1，飞机回报锁定且公共输出 0。原始证据复用 `build/flight_buttons_runtime.log` 的 `GYRO_SCHEDULING_FIX_VERIFICATION` 段；未执行解锁或电机测试。

### 单信号手势测试

识别在 ESP32 上运行，上位机显示设备输出的一个 `gesture` 编号。它是互斥枚举，不是位掩码；同一时刻最多高亮一个手势。

| gesture | 唯一信号 | 识别规则 |
| --- | --- | --- |
| 0 | 无动作 | 中立确认期间、过渡姿态或 IMU 无效；不执行动作，也不延续上一方向 |
| 1 | 平放前进 | 掌心松开、两个角度均在 ±10° 内连续保持 1 秒，输出 Pitch=1700 |
| 2 | 左倾 | 相对 roll 为负且选中横滚方向 |
| 3 | 右倾 | 相对 roll 为正且选中横滚方向 |
| 4 | 手抬起 | 相对 pitch 为正且选中俯仰方向 |
| 5 | 手下垂 | 相对 pitch 为负且选中俯仰方向 |
| 6 | 掌心按住保持 | 手掌按钮按住，优先覆盖所有姿态信号；四轴 1500，停止方向与升降指令 |

手平放、静止后点“手平放后校准”。依次左右倾斜、向上抬起手指端、向下垂下手指端，再按住/松开按钮。这里“抬起/下垂”由俯仰角识别；保持手掌水平上下平移不会触发。每次按钮按下输出掌心保持，松开后立即识别当前方向；若平放则重新等待 1 秒后前进，原来的短按切换灯效和长按开关灯效仍有效。

方向和掌心按住快速响应，只有平放前进延迟确认。倾斜达到 20° 且主轴幅度比另一轴至少大 10°，当前采样就输出方向；可以直接在上下左右之间切换，无须回平放，也没有 300 ms 停稳等待。串口每 100 ms 更新一次，实际显示还受采样和界面刷新影响。握拳使用已有按钮消抖，优先覆盖方向。

当前方向在主轴仍超过 12°、且比另一轴至少大 5° 时保持；其他明确方向可以立即接替。离开方向判定范围后输出 0（无动作），不延续旧方向。仅当没有方向或握拳、且两个角度均在 ±10° 内连续保持 1000 ms，才输出 1（平放前进）。任何离开平放范围、方向动作、握拳或无效数据都会打断中立计时。斜向不明确且不能保持原方向时输出 0，不计为中立。

上位机等待时显示“平放确认中 · 1 秒”，所有动作卡片不高亮；满 1 秒才高亮平放前进。尚不在平放范围且没有明确动作时显示“过渡中 · 无动作”。该规则避免左右/上下切换短暂经过平放时触发前进；其他明确方向仍快速响应。

飞行通道映射只在 `TX_ALT_LIVE`（正常定高控制）和 `TX_ALT_MANUAL`（降级手动）应用；锁定、解锁、自动起飞、降落和恢复定高期间继续发送中位方向通道。掌心保持不会发送急停或关闭电机；若已退出定高，只保持当前推力，不能保证高度和位置不变。

2026-10-04 新手势版验证：通道/手势联合测试、HC3 状态机及实体飞行按键测试通过；33 项上位机测试通过；ESP-IDF 6.0.3 编译及烧录哈希校验通过。烧录后只读 10 秒共 101 帧，默认 `out_axis=1`，平放输出 `[1500,1700,1500,1500,2000,1000,1000,1000]`，`tx_phase=0`、`tx_count=0`，未启动电机。串口记录复用 `build/flight_buttons_runtime.log`。

通道与状态联合测试：`cc -Wall -Wextra -Werror -std=c11 -I main tests/test_control_output.c main/control_output.c main/gesture.c main/tx_control.c -lm -o build/test_control_output && ./build/test_control_output`。覆盖掌心优先、平放 1 秒确认、短暂经过平放不前进、Yaw/Roll 切换及起飞阶段不输出前进。

若实际左右或上下相反，在界面勾选对应的“左右反向”或“上下反向”；若左右动作影响的是上下角度，勾选“交换俯仰/横滚”后再检查方向。校准和方向设置下发到固件，设备状态回传后才更新显示，仅保存在内存中；重启后会自动重新校准零偏和平放零点，方向设置仍需重新选择。角度显示使用与识别相同的相对角度，原始 `pitch` / `roll` 仍保留在串口帧中。

| 字段 | 含义 |
| --- | --- |
| `v`, `ms` | 帧版本（当前为 1）和上电毫秒数 |

| `key_start`, `key_stop`, `key_start_count`, `key_stop_count` | LED1 / LED2 是否按下及累计次数 |
| `key_status`, `key_reason`, `key_local`, `key_pending`, `key_stop_latched`, `key_auto` | 按键/自动连接流程、原因、本地心跳、待完成起飞、急停保持、上电自动连接模式 |

手势设置命令均以换行结束：`@G,ZERO` 以最新有效姿态校准平放，`@G,RESET` 清除平放零点（保留方向设置），`@G,DIR,<上下反向>,<左右反向>,<交换轴>` 设置三个 0/1 开关，例如 `@G,DIR,1,0,0`。IMU 无有效新数据时拒绝平放校准。控制端应使用 `gesture` 作为唯一动作信号；其他字段用于显示和诊断。

手势逻辑测试：`cc -Wall -Wextra -Werror -std=c11 -I main tests/test_gesture.c main/gesture.c -lm -o build/test_gesture && ./build/test_gesture`。上位机控件测试：`python3 -B tests/test_host.py`（需要图形桌面，只使用模拟串口，不触碰硬件）。2026-10-02 已通过四方向立即互切、短暂经过平放不触发中立、满 1 秒确认中立、离开平放/握拳打断计时、握拳释放、校准与方向、无效数据及计时回绕测试；上位机 8 项控件测试通过（含无线数据、输出预览、配置回传和超时清空）。实际佩戴的动作手感仍需用户测试。

上位机发送 ASCII 命令 `@M,<通道>,<强度>,<毫秒>\n`，例如 `@M,0,70,500\n` 表示电机 0 以 70% 运行 500 ms；`@M,0,0,0\n` 立即关闭。通道只能为 0 或 1，强度 0～100，时长 0～2000 ms。桌面程序使用已安装的 [pySerial](https://pyserial.readthedocs.io/en/latest/shortintro.html)，PWM 使用 ESP-IDF [LEDC 驱动](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-reference/peripherals/ledc.html)。

MAX30102 正常时先打印芯片 ID、每秒 `Red/IR`、历史点数及 `corr/quality/contact_resets` 诊断。血氧使用 `espressif/esp_health 0.1.0`，相关性/周期质量门限为库默认 0.8/0.5；有新 PPG 就计算，不等待固定 500 点窗口。指腹轻贴、完整覆盖光窗；新有效结果直接更新，算法暂时无效时保留本次接触上一笔有效值并标注等待更新，移开后清空。I²C 故障或串口离线清空显示。原始信号与血氧有效性分开上报，百分比准确性尚未通过参考仪器验证。
